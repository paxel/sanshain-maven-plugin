# Sanshain Maven Plugin - Project Standards & Intelligence Manifest

## The "Never Again" List (Eradicated AI Patterns)
The following patterns were identified as logical failures or fragile constructs in the legacy AI-generated codebase and MUST NOT be re-introduced:

1.  **Redundant Payload Objects**: Do not create specific static inner classes for every API endpoint variation (e.g., `ProvidePayload`, `ProvideAsyncApiPayload`). Use generic, metadata-driven payloads with `@JsonAnyGetter` to handle varying field names (e.g., `openapi_yaml` vs `asyncapi_yaml`).
2.  **Dead Shadow Methods**: Avoid implementing new logic while leaving old, unused methods (like `buildProvideJson`) that perform similar tasks. Always refactor or delete the "shadow" code.
3.  **Redundant Parameter Resolution**: Mojos MUST NOT implement their own parameter resolution logic if a `Delegate` or `Config` object is available. Resolution of `serviceName`, `url`, and `token` must be centralized to ensure consistency across goals.
4.  **Fragile Hex Conversion**: Never use `Integer.toHexString` without manual zero-padding or `String.format("%02x")` when converting byte arrays (hashes/IDs).
5.  **Implicit Charsets**: Always explicitly specify `StandardCharsets.UTF_8` when calling `getBytes()` or creating `InputStreamReader`s.

## Skillset Injection for Future Development

### Security
- **Token Handling**: Tokens are sensitive. Ensure they are never logged at any level above `DEBUG`. Centralize token resolution in `SanshainMojoDelegate` to respect `settings.xml` and environment variables.
- **Insecure SSL**: The `insecure` flag should only be used for local development. Ensure the `TrustManager` implementation remains isolated and doesn't leak into global HTTP client configurations.

### Performance
- **Caching**: The `.sanshain-cache.json` in the `target` directory is the primary mechanism for avoiding redundant network calls. Always check the hash before `provide` and use ETags for `require`.
- **HttpClient**: Reuse `java.net.http.HttpClient` instances where possible (currently managed per-Mojo execution).

### Deployment & Maintenance
- **Version Detection**: The plugin uses `JGit` for branch detection. In CI environments, always prefer environment variables (e.g., `GITHUB_REF_NAME`) over JGit's detached HEAD resolution.
- **Strict Mode**: Use `sanshain.strict=true` in production pipelines to ensure that configuration missing errors or network failures break the build.

## Architectural Hardening
- **Composition over Inheritance**: Use `SanshainMojoDelegate` to share logic between `ProvideMojo` and `RequireMojo`. Avoid deep inheritance hierarchies.
- **Immutable Payloads**: Prefer `final` fields and constructor-based initialization for JSON payload objects to ensure thread safety and clarity.
